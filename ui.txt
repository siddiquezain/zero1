Build a restrained professional palette.

The application concerns:

🔥 fire
🚨 alerts
🛰️ satellite intelligence
🗺️ geospatial monitoring
📊 risk analysis

Therefore the UI should have a neutral foundation with carefully controlled semantic colors.

Use color primarily to communicate:

* Severity
* Risk
* Status

# LAYOUT PHILOSOPHY

Avoid the classic:

```text
Sidebar
--------------------------------
Card | Card | Card | Card
--------------------------------
Huge chart
--------------------------------
Another row of cards
```

That is generic dashboard UI.

Instead, create a **spatial hierarchy**.

The most important information should dominate the viewport.

For the main monitoring screen, think in terms of:

```text
GLOBAL NAVIGATION

┌──────────────────────────────────────────────┐
│ SYSTEM STATUS / CONTEXT / TIME              │
├──────────────────────────────────────────────┤
│                                              │
│              PRIMARY MAP                     │
│                                              │
│     High-value geospatial information        │
│                                              │
│        contextual intelligence               │
│                                              │
├──────────────────────┬───────────────────────┤
│ ACTIVE INTELLIGENCE  │ RISK / ALERT SUMMARY │
├──────────────────────┴───────────────────────┤
│ TIMELINE / HISTORICAL CONTEXT                │
└──────────────────────────────────────────────┘
```

But do NOT blindly follow this layout.

Use your design judgment after inspecting the existing product.

# MICRO-INTERACTIONS

Motion should make the application feel alive, not animated for decoration.

Use subtle animation for:

* Page transitions
* Panel appearance
* Alert arrival
* Map selection
* Timeline movement
* Hover states
* Data refresh
* Loading states
* Number changes
* Expand/collapse

Prefer short, purposeful transitions.

Avoid:

* Bouncy everything
* Excessive spring animations
* Constant pulsing
* Distracting background animations
* Animation on every component

If an animation does not improve comprehension, remove it.

---

# LOADING STATES

Replace generic spinners wherever possible.

Use:

* Skeletons
* Progressive loading
* Contextual indicators
* Subtle shimmer where appropriate

Loading should preserve the layout so the interface doesn't jump.

---

# EMPTY STATES

Every empty state should communicate:

1. What is empty
2. Why it may be empty
3. What the user can do

Avoid:

```text

```

Make them feel intentional and professional.


* Sections
* Dividers
* Typography

* Panels
* Tables
* Inline metadata

# CRITICAL RULE: ITERATIVE IMPLEMENTATION

Do NOT attempt to blindly rewrite the entire application in one huge change.

Work screen-by-screen.

After each major screen:

1. Run the application.
2. Inspect the result.
3. Compare against the intended visual direction.
4. Fix spacing/alignment/typography.
5. Check responsive behavior.
6. Check that functionality still works.
7. Continue to the next screen.

If visual inspection/browser tooling is available, **use it extensively**.

# AI-SLOP DETECTION CHECK

Before considering the redesign complete, critically inspect the UI and ask:

### Does this look like a generic AI-generated dashboard?

If YES → redesign it.

Specifically look for:

* Too many cards
* Too many gradients
* Excessive rounded corners
* Excessive glassmorphism
* Generic purple/blue gradients
* Random accent colors
* Huge meaningless numbers
* Excessive shadows
* Decorative icons
* Excessive badges
* Excessive animations
* Inconsistent spacing
* Generic dashboard layouts
* Components that don't feel intentionally designed

Remove them.
